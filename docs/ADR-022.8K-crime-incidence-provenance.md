# ADR-022.8K — Crime Incidence Dataset Provenance

## Estado

**ACTIVO — DATASET AGREGADO INSTITUCIONAL**

## Objeto

Este ADR gobierna la procedencia, identidad, cobertura temporal y admisión del dataset utilizado por el módulo autónomo de Incidencia Delictiva del PERFILADOR REMOTO SSPE-CEIPOL.

La colección productiva no representa un único delito ni un único año. Integra 53 archivos CSV históricos de incidencia operacional con múltiples tipologías delictivas.

## Identidad gobernada

```text
CRIME_INCIDENCE_DATASET_NAME=Colección Histórica de Incidencia Delictiva 911 - Aguascalientes
CRIME_INCIDENCE_DATASET_VERSION=2016-2026-C5I-911-AGG-v1
CRIME_INCIDENCE_SOURCE_ORGANIZATION=C5i de la Secretaría de Seguridad Pública del Estado de Aguascalientes
CRIME_INCIDENCE_DATASET_TEMPORAL_START=2016-01-01
CRIME_INCIDENCE_DATASET_TEMPORAL_END=2026-06-23
```

## Naturaleza de la versión

`2016-2026-C5I-911-AGG-v1` es un identificador interno de gobernanza del PERFILADOR REMOTO para la colección agregada activa. No debe interpretarse como número de versión documental emitido por C5i.

## Organización fuente

La procedencia institucional documentada corresponde al C5i de la Secretaría de Seguridad Pública del Estado de Aguascalientes.

No debe atribuirse esta colección al SESNSP ni a una fuente externa distinta sin evidencia documental específica.

## Cobertura temporal gobernada

La cobertura analítica admitida es:

```text
2016-01-01 <= FECHA <= 2026-06-23
```

Existen registros fuente con fechas anteriores a 2016 que permanecen preservados en sus CSV originales. No se corrigen, trasladan ni eliminan. El pipeline debe clasificarlos como `TEMPORAL_OUT_OF_SCOPE`.

## Integridad geoespacial

Los registros clasificados como `GEO_INVALID` permanecen excluidos del subconjunto analítico admitido. El sistema no debe fabricar, dispersar, trasladar ni sustituir sus coordenadas.

## Adaptadores de fecha reconocidos

El pipeline canónico admite actualmente:

- `FECHA`
- `FECHA_DENUNCIA`
- `FECHA_REP`

Los valores fuente se normalizan sin reescribir físicamente los CSV.

## Dataset observado en cierre C1

Antes de activar el firewall temporal definitivo, la auditoría canónica produjo:

```text
CSV: 53
RECIBIDOS: 85628
ACEPTADOS UNICOS: 85352
RECHAZADOS GEO_INVALID: 9
DUPLICADOS: 267
```

La colección contiene además 14 registros anteriores a 2016 que deben quedar fuera del subconjunto gobernado mediante el firewall temporal.

Resultado esperado después de activar el contrato temporal:

```text
RECIBIDOS: 85628
RECHAZADOS ESPERADOS: 23
  GEO_INVALID: 9
  TEMPORAL_OUT_OF_SCOPE: 14
DUPLICADOS ESPERADOS: 267
ACEPTADOS UNICOS ESPERADOS: 85338
```

Los conteos definitivos deberán ser confirmados mediante ejecución del pipeline y no asumidos por documentación.

## Reglas de preservación

1. Los CSV fuente no se modifican para conseguir admisión.
2. Las fechas anómalas no se sustituyen por fechas inferidas.
3. Las coordenadas inválidas no se corrigen sintéticamente.
4. Los duplicados no cuentan dos veces.
5. La admisión debe ejecutarse a través del pipeline ADR-022.
6. El módulo de Incidencia permanece independiente de expedientes, fotografías y Street View.

## Configuración de despliegue

La provenance gobernada se configura mediante variables de entorno del servidor.

En desarrollo local, los valores deben residir en `.env.local` y este archivo no debe incorporarse al repositorio.

En producción, los mismos cinco valores deben configurarse en **Vercel project Environment Variables** para el entorno **Production**.

Las variables requeridas son:

```text
CRIME_INCIDENCE_DATASET_NAME
CRIME_INCIDENCE_DATASET_VERSION
CRIME_INCIDENCE_SOURCE_ORGANIZATION
CRIME_INCIDENCE_DATASET_TEMPORAL_START
CRIME_INCIDENCE_DATASET_TEMPORAL_END
```

No se deben hardcodear estos valores dentro de rutas API, componentes React ni motores de análisis.

## Criterio de certificación

C1 se considera cerrado únicamente cuando producción muestre:

```text
GOBERNANZA ADR-022
ADMITTED
```

y la provenance no reporte metadatos faltantes.
