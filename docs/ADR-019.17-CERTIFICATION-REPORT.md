## A. CAMBIOS REALIZADOS

1. **Gobernanza del Bridge Temporal (Objetivo 1)**:
   - Se refactorizó `src/services/geoint/temporalComparisonBridge.ts`.
   - Se implementó la función pura `UniversalEvidenceComparisonToFinding` que garantiza un mapeo determinístico de todos los campos obligatorios: `expedienteId`, `traceabilityId`, `sourceEvidenceId`, `coordenadas` (coordenadas de la vista panorámica), `imagen` e `estado` normalizado.
   - Se eliminaron mapeos silenciosos y campos legacy inexistentes.
   - Se conservó un alias de retrocompatibilidad `buildStreetViewFindingFromTemporalComparison`.

2. **Persistencia Temporal Certificada (Objetivo 2)**:
   - Se verificó la existencia operativa de los endpoints de la API Next.js:
     - `POST /api/expedientes/[id]/geoint/temporal-comparisons`
     - `GET /api/expedientes/[id]/geoint/temporal-comparisons`
     - `PATCH /api/expedientes/[id]/geoint/temporal-comparisons/[comparisonId]`
   - Se garantizó que la fuente primaria de datos al recuperar comparaciones provenga del backend (Firestore a través de la API REST) cuando se ejecuta en el navegador. El mapa de memoria `inMemoryComparisonStore` y el estado React local actúan únicamente como un **fallback controlado** en caso de fallos de red o entornos aislados de pruebas.

3. **Gobernanza de Estados Unificados (Objetivo 3)**:
   - Se consolidó el uso exclusivo de los estados canónicos definidos en el enum `GeointGovernanceStatus` de `src/types/geointGovernance.ts`:
     - `PENDING_REVIEW`
     - `APPROVED_EVIDENCE`
     - `REJECTED_FINDING`
   - Se utiliza la función adaptadora legacy `normalizeGeointGovernanceStatus()` para traducir dinámicamente cualquier estado histórico (`APROBADO`, `IGNORADO`, `PENDIENTE_REVISION`, `GENERADO`) sin alterar datos existentes en bases de datos de producción.

4. **Trazabilidad Forense Multi-Estadio (Objetivo 4)**:
   - Se auditó la cadena de custodia de la evidencia GEOINT. Ningún componente o proceso del sistema puede omitir la asignación del `traceabilityId` y del `sourceEvidenceId` desde la ingesta original.
   - Cadena obligatoria:
     `Fotografía original (Campo) -> GeoEvidence -> StreetView Panorama -> Temporal Comparison -> Finding -> Report`
   - Los tests automáticos verifican la conservación de esta trazabilidad a lo largo del flujo de datos del bridge y del backend.


5. **Integración Controlada del Barrido (ADR-018 - Objetivo 5)**:
   - Se auditó el motor de barrido controlado `GeointControlledSweepEngine.tsx`.
   - Los hallazgos generados se envían al circuito único unificado:
     `Sweep -> Evidence -> Human Validation (StreetViewFindingsPanel) -> Finding Persistence -> Report`
   - Se eliminó cualquier posibilidad de una ruta paralela o persistencia local sin control analítico.

6. **Estructura de Gobernanza de Event Log (Objetivo 6)**:
   - Se diseñó la estructura y se creó el archivo de tipos y auxiliares `src/types/geointEventLog.ts`.
   - Soporta eventos críticos: `GEOINT_SWEEP_STARTED`, `PANORAMA_VALIDATED`, `TEMPORAL_COMPARISON_CREATED`, `HUMAN_APPROVED` y `REPORT_CONSUMED`.
   - Contempla de forma obligatoria los atributos: `eventId`, `timestamp`, `expedienteId`, `traceabilityId`, `actor`, `source` y `status`.

## E. RIESGOS RESTANTES

1. **Dependencia de API Key de Google Street View**:
   - *Riesgo*: Cambios de cuotas o validez de la API Key de Google Maps pueden limitar la carga de imágenes dinámicas.
   - *Mitigación*: El sistema implementa fallbacks robustos controlados que indican "SIN VISTA PREVIA" sin alterar la lógica de gobernanza ni los metadatos espaciales.
2. **Uso de Conexión Local / Fallback**:
   - *Riesgo*: Si el navegador se desconecta temporalmente del backend de Firestore, el almacén de memoria `inMemoryComparisonStore` retiene temporalmente las operaciones.
   - *Mitigación*: Se sugiere IndexedDB (Dexie) para sincronización robusta offline-first en el futuro.
